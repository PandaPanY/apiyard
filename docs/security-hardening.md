# 2026-11 安全修复与升级说明

本轮修复对应 [项目审计](audit-2026-11-12.md) 的 A1–A7。升级前停止服务并备份 SQLite 数据库；新建的 `project_credentials` 表由启动时的数据库迁移自动创建。

## 私有数据

私有项目的角色查询和聚合动态遵守项目查看权限。分组动态只聚合调用者可见的项目，分组本身的动态只对分组成员可见。个人空间的完整元数据不向无权访问的用户返回。

## 项目 token

- 项目设置页获取的 token 改为 32 字节密码学随机数，仍输出 64 位十六进制，HTTP 路径和 token 参数用法不变。token 对应的项目和签发用户保存在 SQLite 中，不从客户端提交的加密内容中提取授权身份。
- 同一用户重复获取同一项目的 token 时保持不变；重置项目 token 同时吊销该项目全部新凭据和旧 token。
- 新凭据每次调用均使用签发用户的当前权限。降为访客后不能继续写入，移除成员后不能继续访问私有项目。
- 原有 YApi 加密 token 和原始项目 token 仍可用于兼容开放 API，但统一视为项目内的 `system` 集成凭据，只授予查看、编辑接口的能力。**加密 token 中的 uid 不再授予用户或管理员身份。** 它们不能修改项目设置；动态记为 system。
- 旧凭据属于项目级能力，不能随某个用户降权自动失效；若原先交给某人的旧 token 需要撤销，应重置项目 token。需要按个人权限控制的集成，应重新从项目设置页获取新 token。
- 原来的 `-token-salt` 仅用于解码迁移来的旧 token；新凭据不依赖默认口令。
- MCP 仅接受 ApiYard 新签发的 token，并检查签发用户当前是否仍有项目查看权限。已有旧 token 的客户端需重新获取。
- v0.1.1 默认关闭仍在开发的 MCP 入口；只有显式设置 `-mcp on` 或 `readonly` 才启用基础接入。完整工具及客户端验收属于 v0.2。

这会收紧旧 token 的项目管理能力，并让旧原始 token 具备所属私有项目的读取能力。它与 YApi 原来不一致的权限细节属于明确的安全兼容性变更。常规接口导入、查询、保存等用法不需要改 URL；需要修改项目配置的集成请换用具有管理权限用户的新 token。

## Mock 资源预算

Schema 与 Mock.js 生成器限制节点处理总量 10,000、单项长度或重复次数 10,000、累计字符串与键字节预算 2 MiB，并限制递归深度。输入检查、生成、输出检查会共同消耗预算，因此实际最大数组或输出长度可能更小。嵌套重复、占位符、正则生成都受限；生成过程检查请求取消。

Mock 路由与 Schema 示例生成共享 8 个并发名额；超过并发返回 HTTP 429，超出生成预算返回受控错误。原先依赖超大生成结果的模板需要拆分。普通模板的输出规则保持兼容。

## 迁移可靠性

- 同一迁移目标使用排他锁文件；临时库使用同目录唯一文件名。
- 替换前拒绝存在 WAL、SHM、journal 的目标库；迁移前请先停止 ApiYard，正常关闭会完成 WAL checkpoint。
- 覆盖已有库时，先创建并同步持久备份 `数据库名.before-migrate-*`，再直接替换，不先删除旧库。备份路径会打印在迁移进度中，确认新库正常后可自行归档或删除。
- 如果替换失败，旧库和备份保留；即使进程在替换阶段异常终止，也可从备份恢复。临时文件和 `.migrate.lock` 可能因异常终止而残留；确认没有迁移进程、保留所需备份后再清理锁文件。

## 依赖与发布

压缩库升级至 v1.20.2，调用链扫描额外发现的 x/text 无限循环问题通过升级至 v0.39.0 修复。CI 与发布验证增加固定版本 govulncheck。二进制和镜像发布均依赖同一套测试、vet、漏洞检查成功，避免失败版本更新镜像标签。Release 增加 `modules.json` 依赖清单及其 SHA-256；该清单是 Go 模块清单，不是完整前端 SBOM。
