# 与 YApi 的差异

ApiYard 以兼容为第一目标：界面就是 YApi 1.12 的原版前端，接口路径、响应格式、开放 API 和 Mock 地址都与原版一致，现有的周边工具改个服务器地址就能用。下面是使用者能感受到的不同之处。逐条的技术细节（包括只在越权、异常请求时才看得出的差异）见 [architecture.md](architecture.md#与-yapi-刻意不同的地方)。

## 部署

| | YApi | ApiYard |
|---|---|---|
| 运行环境 | Node.js + MongoDB | 一个可执行文件，数据在一个 SQLite 文件里 |
| 配置 | `config.json` | 命令行参数或环境变量，对照表见 [deployment.md](deployment.md#与-yapi-的-configjson-对照) |
| 初始管理员密码 | 固定为 `ymfe.org` | 随机生成，只在首次启动的日志里出现一次；也可以用 `-admin-password` 指定 |
| 端口 | 3000 | 3000 |

## 暂不支持的功能

界面上对应的入口已经隐藏。直接输入地址（如 `/project/11/wiki`）仍能打开页面，但后端没有这些接口（返回 404），页面里加载不出数据。

| 功能 | 说明 |
|---|---|
| 自动化测试（测试集合） | 计划在之后的版本支持；迁移时这部分数据不会导入，报告里会列出条数 |
| 高级 Mock（期望、接口级脚本） | 同上 |
| 项目的全局 Mock 脚本 | **不会支持执行**。原版的远程代码执行漏洞就出在这里。开启了脚本的项目，Mock 照常返回数据，但脚本被忽略，响应头里有 `X-ApiYard-Mock-Script: ignored`；迁移报告也会列出这些项目 |
| Wiki、系统信息（统计）、Swagger 自动同步、导出 PDF | 原版的插件功能，计划按反馈再决定 |
| 从 URL 导入 Swagger | 服务端去请求任意地址有 SSRF 风险，暂不提供；把文件下载下来再导入即可 |
| LDAP 登录、第三方登录插件 | 暂不支持 |
| 邮件通知 | 不发送邮件；成员的通知开关照常保存 |

## 正常使用中能看到的不同

| 位置 | 差别 |
|---|---|
| Mock 数据 | Mock.js 规则和占位符与原版一致，但占位符括号里的参数只按字面量解析，不执行代码（原版用 `eval`）。JSON Schema 的 Mock 会生成全部字段，数组有 1–3 项；原版因为依赖库的缺陷，非必填字段随机缺失、数组总是空的 |
| Mock 响应头 | 多了 `Content-Security-Policy: sandbox` 等安全响应头，在浏览器里直接打开 Mock 地址时，返回的 HTML 不能在 ApiYard 的页面里执行脚本；fetch、XHR 调用不受影响 |
| HTML 导出 | 内容相同，样式和目录的生成方式略有不同 |
| 动态列表 | 同一秒内的多条动态，顺序固定按发生的先后 |
| 修改用户名、邮箱 | 所有分组、项目里的成员信息都会同步（原版只同步第一个） |
| 外部请求 | 原版前端会把服务器地址发给 Google Analytics、请求外部网站检查新版本；ApiYard 都拦截了，内网部署不向外发送任何数据 |

## 安全修复

原版有不少接口不检查权限，例如任何登录用户都能拿到任意项目的 token、往任意分组加人、导出私有项目；开放 API 的 token 能修改其他项目的接口。ApiYard 都按原版界面上的权限规则做了检查，并修复了动态内容的存储型 XSS。正常使用时这些检查不会挡住任何操作，完整清单见 [architecture.md](architecture.md#只影响异常请求或未授权请求)。
